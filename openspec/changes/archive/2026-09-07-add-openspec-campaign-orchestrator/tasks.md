## 1. Orchestrator script (`openspec-campaign.js`)

- [ ] 1.1 Create `openspec-campaign.js` at the repo root (next to `openspec-plan-change.js`, edit at source) with the house-style header: `export const meta` describing the campaign fan-out planner, engine-shaped async function body (top-level await/return legal), and named phases matching the dynamic flow in `design.md` (Resolve, Scaffold, Plan, Compose). Informed by: `specs/campaign-orchestrator/spec.md`, `design.md` Context/C4 sections, existing `openspec-plan-change.js` shape.
- [ ] 1.2 Implement the defensive args parse per `design.md` Decision 8: accept `items` (optional array — explicit items win outright with no discovery merge), `intent` (string forwarded verbatim into each plan-change invocation), `repoRoot`/`store` (forwarded into shell prefixes exactly as `openspec-plan-change.js` does); defensively parse a JSON-encoded string args transport. No `depth` or `planMode` argument exists in v1 (Decision 3 / spec "one level deep").
- [ ] 1.3 Implement item resolution before any per-item work: when `items` is omitted, dispatch a minimal discovery agent that runs `openspec list` and returns pending change names with each item's discovery source recorded (spec: "Discovery falls back to openspec list"); an empty discovery result is a degenerate zero-item campaign that skips per-item work and composes a zero-item digest without aggregate failure (spec: "Empty discovery yields a degenerate campaign"). Informed by: `design.md` Decision 6.
- [ ] 1.4 Implement strictly serial scaffolding: one scaffold agent at a time via `openspec new change`, each awaited before the next dispatches — no two scaffolds in flight (spec: "Scaffold steps never overlap"); a scaffold failure records `failed` for that item without retry and later items still scaffold (spec: "Scaffold failure does not stop later scaffolds"). Informed by: `design.md` Decision 2 (global-mutating operation, ADR-0001 prohibition class).
- [ ] 1.5 Implement the one-level-deep planning fan-out: after scaffolding settles, invoke `workflow('openspec-plan-change')` exactly once per item concurrently, with default `planMode: 'one'` (proposals-only); the orchestrator never nests plan-change beneath plan-change, and deeper authoring is left to an explicit host re-invocation per item (spec: "Default planning is proposals-only", "Plan fan-out stays one level deep"). Informed by: `design.md` Decision 3.
- [ ] 1.6 Implement per-item outcome classification — exactly one of `ok` / `needs_input` / `failed` per item: written artifact with passed QA → `ok`; a `needs_input` return from plan-change or a checkpoint-bridge escalation → `needs_input` carrying the batched question text verbatim; a null plan-change result or resolve failure → `failed` (null-as-failed). A failed or blocked item never blocks or restarts siblings; no automatic retries — the host decides re-runs; a skipped/absent item is never recorded as success (spec scenarios: "Plan-change result maps to a per-item outcome", "Blocked item does not block siblings", "No automatic retry of a failed item", "Skipped item is never recorded as success"). Informed by: `design.md` Decision 4 (null-as-failed vs ADR-0002's null-as-blocker rationale).
- [ ] 1.7 Implement shard emission and the composer step: each per-item branch emits a compact shard record (item, mode, outcome, written path, question/assumption lines); one schema-validated composer agent folds the shards into a single `CAMPAIGN.md` in the repo root with per-item outcomes, aggregate counts per outcome, and per-item next actions (re-run, interview, or ready for review); if composition is ambiguous, ask the host at most once with all questions batched via checkpoint-bridge, and with no host answer record the ambiguity verbatim in the digest instead of guessing. Informed by: `design.md` Decision 5, spec "Shard digest composed into CAMPAIGN.md" scenarios.
- [ ] 1.8 Enforce the hard prohibition as verbatim prompt-contract lines: every agent prompt (discovery, scaffold, composer) carries the family contract lines mirroring `openspec-plan-change.js`'s constants — never run `openspec apply`, `openspec archive`, or `openspec update`; never move or sync state. Post-check the composed digest for apply/archive/update instruction strings and strip/record any violation as an assumption line rather than shipping it; the digest always directs the host to review and decide apply/archive in the main session, even when every item is `ok` (spec: "Digest never directs implementation", "Prohibition holds even when items are all complete"). Informed by: `design.md` Decision 7, ADR-0001/ADR-0002 trust model.
- [ ] 1.9 Implement the structured return: return only the digest path plus aggregate outcome counts — never full shard contents — keeping shard bodies in the composer's context per the ADR-0001 containment argument. Informed by: `design.md` Risks ("Large campaigns still grow main-session context").
